# Database (Phase 2)

Schema: `prisma/schema.prisma` (Doc C). Migrations: `0001_baseline` (generated by `prisma migrate diff --from-empty`) and
`0002_indexes_checks` (hand-written raw SQL). Operator-applied role grants: `prisma/operator/0003_db_roles.sql.template`
(deliberately outside `prisma/migrations`, never auto-run).

## Deviations from Doc C (all deliberate)
1. **`sla_active_unique`** — Doc C's `coalesce("ticketType"::text,'*')` index is rejected by Postgres (enum→text cast is not
   IMMUTABLE). Replaced by two partial unique indexes (`sla_active_unique_typed`, `sla_active_unique_all_types`) with the same rule.
2. **`Ticket.search`** — the generated tsvector column is declared `GENERATED ALWAYS` directly in `0001_baseline` (one manual
   edit, noted in the file) so no `DROP COLUMN` is ever needed, and is modelled in `schema.prisma` with `dbgenerated(...)` so the drift
   check stays clean. The app never writes it.
3. **pgcrypto not enabled** — UUIDs are generated by Prisma; no extension is needed. `pg_trgm` is optional: if it cannot be created
   the migration falls back to a prefix index on `lower("displayName")`.
4. Extra CHECK constraints beyond Doc C: priority-override reason, non-negative SLA pause, positive SLA minutes, calendar
   bounds/workdays, attachment size, attachment link state (linked ⇔ has ticket), job attempts.

## Ticket numbers
`allocateTicketNumber(tx)` takes `nextval` of the `Ticket.number` sequence; `formatReference` derives `INC0001042` / `REQ0001043`
(format [OPEN]). Verified: 20 parallel inserts give 20 distinct numbers and references.

## Guards
- Runtime: `assertSafeDatabase` (startup, `src/instrumentation-node.ts`, and the seed) refuses a database that has a `Tenant` table or
  `_prisma_migrations` rows not in `KNOWN_MIGRATIONS` (`src/platform/db/knownMigrations.ts`; a unit test keeps it in sync with the
  migrations directory).
- Tests: `tests/integration/setup.ts` only connects to localhost/127.0.0.1/postgres and a database name ending in `_test`.

## Seed (reference data only)
`npm run db:seed:reference` — idempotent, never overwrites admin edits. Creates: `ticket.autoCloseDays=5`,
`ticket.reopenWindowDays=7` ([OPEN]); a `24x7` UTC calendar; the `Service Desk` triage group; a placeholder `General` category
([OPEN]); four placeholder 24×7 SLA policies ([OPEN] — targets are NOT confirmed). No employees, no accounts.
